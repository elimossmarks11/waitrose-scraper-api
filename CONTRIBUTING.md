# Contributing Guidelines

This document explains how the scraper was built, the tools and resources used, and provides code-level details for developers who want to understand or extend the codebase.

```bash
conda env create -f environment.yml

```

```bash

```

## Adding a New Endpoint

1. Define any new response models in `api/models.py` using Pydantic `BaseModel` with `Field` descriptions.
2. Add the route in `api/main.py`. Use parameterised SQL queries (`?` placeholders) to prevent injection.
3. Follow existing patterns: use `get_db()` for database access if refactored, or the global `con` connection. Use `apply_fields()` if the endpoint should support field masking.
4. Add a summary and `response_model` to the decorator for Swagger documentation.

## Adding New MUP Markers

The MUP lookup table (`data/enriched/MUP.xlsx`) contains 109 markers from Neumann et al. (2023). To add or modify markers:

1. Edit `MUP.xlsx`. Each row needs `category`, `mup_id`, `mup_name`, `individual_compound`, `match_type` (either `exact` or `prefix`), and `is_extended`.
2. Re-run enrichment: `python run_pipeline.py enrich-open-food-facts --all`
3. Rebuild the database: `python run_pipeline.py build-db`

Substring matching is used for `exact` terms and `str.startswith()` for `prefix` terms. Be aware that short marker terms may produce false positives (see Limitations in README).

## Adding Excluded Categories

To exclude a new product category (e.g. pet food, household items):

1. Find the Waitrose category ID from the product data or the `/categories` endpoint.
2. Add the ID to `excluded_categories.py` with a comment.
3. Re-run the pipeline to regenerate enriched data and the database.

## Improving Classification Accuracy

Known areas for improvement:

- **OFF barcode mismatches.** Some OFF entries appear to be for different products sharing the same barcode. The `/products/{id}/flag` endpoint supports flagging these for review.
- **MUP false positives.** Substring matching means "starch" matches inside "cornstarch." A word-boundary approach would reduce this but may miss compound terms like "whey protein isolate."
- **Category inference gaps.** 109 products remain "Not confirmed UPF" because they have no ingredients and fall outside the safe category list. Manual review of these categories could reduce this number.

## Code Style

- Type hints on all function signatures.
- Comments explain why, not what.
- Pydantic models include `Field(description=...)` for every field.

## Codebase Guide

The scraper follows a three-stage pipeline: **Middleware → Spider → Pipeline**.

### Selenium Middleware (`supermarkets/middlewares.py`)

`SeleniumMiddleware` intercepts Scrapy requests and loads pages in a browser via Selenium.

**Cookie Banner Handling**: The middleware automatically handles cookie consent banners by clicking the "Reject All" button, using Selenium's `WebDriverWait` to wait for the button to become clickable:

```py
element = WebDriverWait(self.driver, 3).until(
    EC.element_to_be_clickable((By.CSS_SELECTOR, "button[data-testid='reject-all']"))
)
element.click()
```

**Infinite Scroll**: For category pages (identified by `request.meta["load_more"]`), the middleware repeatedly clicks the "Load More" button until no more products are available. It scrolls the button into view and uses JavaScript clicks to avoid visibility issues:

```py
element = WebDriverWait(self.driver, 5).until(
    EC.element_to_be_clickable((By.CSS_SELECTOR, "button[data-shortdescription='Load more products']"))
)
self.driver.execute_script("arguments[0].scrollIntoView({block: 'center'});", element)
self.driver.execute_script("arguments[0].click();", element)
```

### Spider (`supermarkets/spiders/waitrose.py`)

`WaitroseSpider` manages the crawling lifecycle.

**Request Generation**: `start_requests()` defines the category URLs to scrape. Currently only the "Frozen" category is included. To add more categories, simply append URLs to the `categories` list. The `meta={"load_more": True}` flag tells the middleware to handle infinite scrolling for these pages.

**Data Extraction**: `parse_product()` extracts structured data from the `__NEXT_DATA__` JSON script tag embedded in each product page. The JSON contains the product's name, barcodes, categories, and pricing in a clean, structured format:

```py
json_text = response.css("script#__NEXT_DATA__::text").get()
data = json.loads(json_text)
product = data.get('props', {}).get('pageProps', {}).get('product', {})
```

### Pipeline (`supermarkets/pipelines.py`)

`DeduplicationPipeline` ensures each product appears only once in the output. When a duplicate product name is encountered, the pipeline merges its barcodes into the existing entry and drops the duplicate item:

```py
if name in self.seen_items:
    existing_item = self.seen_items[name]
    existing_barcodes = existing_item.get('barcode')
    for barcode in new_barcodes:
        if barcode not in existing_barcodes:
            existing_barcodes.append(barcode)
    raise DropItem(f"Duplicate item found: {item}")
```
